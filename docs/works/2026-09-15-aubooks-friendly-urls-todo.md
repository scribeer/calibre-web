# Человекочитаемые URL для AU-Books

## Статус
Будущая задача. Реализация НЕ начата.

## Цель
Заменить технические URL вида `/author/stored/13429` на человекочитаемые `/author/имя-автора` для основных сущностей каталога.

## Сущности
- author: `/author/stored/<id>` → `/author/<slug>`
- series: `/series/stored/<id>` → `/series/<slug>`
- category/genre: `/category/<slug>` (уже частично реализовано)
- publisher: `/publisher/stored/<id>` → `/publisher/<slug>`
- language: `/language/stored/<id>` → `/language/<slug>`
- аналогично для других list-страниц, где это имеет смысл

## Требования к реализации

### Slug generation
- Генерация slug из названия сущности.
- Поддержка Unicode и кириллицы.
- Корректное URL-encoding для slug.
- Транслитерация или URL-safe UTF-8 — решить при проектировании.

### Collisions
- Обработка одинаковых названий (два автора с одинаковым именем).
- Стабильность URL после создания slug.

### Стабильность и изменения
- При изменении имени сущности старый URL должен продолжать работать (301 redirect на canonical) или оставаться неизменным.
- Генерация canonical URL для новых и изменённых сущностей.

### Обратная совместимость
- Старые numeric/stored URL (`/author/stored/<id>`) должны продолжать работать или делать 301 redirect на canonical URL.
- Внутренние ссылки в шаблонах и Python-коде должны генерировать новые URL.

### SEO
- Canonical URL на странице списка книг.
- Не создавать дубли страниц для старых и новых URL.
- Sitemap обновляется с новыми URL.

## Не входит в задачу
- Изменение URL detail-страницы книги (`/book/<id>` остаётся).
- Изменение URL поиска и служебных страниц.

## Связанные файлы
- `cps/web.py` — маршруты `books_list`, `author`, `series`, и др.
- `cps/themes/aubooks/templates/` — ссылки в шаблонах.
- `cps/db.py` — модели Author, Series, Tags, Languages, Publishers.

## Риски
- Необходимость миграции базы для хранения slug.
- Производительность: lookup по slug вместо id.
- Влияние на кэширование sidebar и других кэшированных фрагментов.
