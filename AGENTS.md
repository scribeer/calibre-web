# AU-Books Calibre-Web Fork

Этот репозиторий — форк Calibre-Web для проекта AU-Books.

## Git

- `master` — чистая ветка для синхронизации с upstream.
- `aubooks` — основная рабочая ветка AU-Books.
- Не вносить пользовательские изменения напрямую в `master`.
- `origin` — `scribeer/calibre-web`.
- `upstream` — `janeczku/calibre-web`.

## Production

- Не изменять production Calibre-Web на VPS2 без отдельной явной задачи.
- Не выполнять deploy автоматически.
- Не перезапускать production-сервисы.
- Все изменения сначала разрабатывать и тестировать отдельно.

## Разработка

Перед изменениями:

1. Изучить существующую реализацию Calibre-Web.
2. Стараться делать минимальные изменения в upstream-коде.
3. Не переписывать существующий функционал без необходимости.
4. Учитывать возможность будущего обновления из upstream.
5. Не удалять функции только потому, что они пока не нужны AU-Books.

## Дизайн

Основная цель первых задач — адаптация интерфейса Calibre-Web под AU-Books.

Особое внимание:

- простота интерфейса;
- доступность;
- клавиатурная навигация;
- screen reader compatibility;
- корректная семантика HTML;
- минимальная зависимость от обложек и визуальных элементов.

## Тестирование

После каждого изменения:

- проверить затронутую функциональность;
- проверить отсутствие очевидных регрессий;
- запустить существующие тесты, если они относятся к изменению;
- не считать задачу завершённой при наличии известных ошибок.

## Документация

После каждой выполненной задачи создать Markdown-файл:

`docs/works/YYYY-MM-DD-short-task-name.md`

В отчёте указать:

- цель задачи;
- что было изучено;
- какие файлы изменены;
- что именно изменено;
- какие тесты выполнены;
- известные ограничения;
- commit hash, если был создан commit.

Документацию писать на русском языке.
Не добавлять лишние пустые строки.

## Безопасность

- Не публиковать секреты, пароли, токены и ключи.
- Не коммитить `.env` и другие файлы с секретами.
- Не выполнять разрушительные действия без явной необходимости.
